# ytmkit v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship a small, documented Node.js/TypeScript library that gives YouTube Music client authors normalized metadata, search, and playable audio stream URLs behind a clean API.

**Architecture:** `ytmkit` wraps the maintained `youtubei.js` InnerTube client. Our own layer provides (1) normalized, JSON-serializable domain models, (2) a playback session that resolves and refreshes audio-only stream URLs, and (3) a small CLI so non-JS clients can consume the same data as JSON.

**Tech Stack:** TypeScript (ESM, Node 18+), `youtubei.js`, Node `vm` for the player-script evaluator, Vitest for tests, `node:util` `parseArgs` for the CLI.

**Spec:** `docs/DESIGN.md`

## Global Constraints

- Node.js 18 or newer. Package is ESM (`"type": "module"`).
- One runtime dependency only: `youtubei.js` (MIT).
- Public model types are plain JSON-serializable objects; no class instances in returned data.
- Stream resolution returns audio-only formats. Video formats are out of scope for v0.1.
- No credentials are stored. The cookie option is passed straight to `youtubei.js`.
- All public methods validate their inputs and reject with `YtmkitError`.
- Tests never require the network unless `YTMKIT_LIVE=1` is set.

## Review Focus

- A track returned from an album where `artists` is missing upstream must still carry the album artist.
- A playlist with many pages must stop at `limit` and not loop forever when continuations repeat.
- A stream URL without an `expire` parameter must report `expiresAt: null`, not an invalid date.
- A network/InnerTube failure must reject with `YtmkitError` carrying the original error as `cause`.
- `search()` must return the same object shape for every query, even when a category is empty.
